# 请求日志账户元数据设计

## 背景

请求详情抽屉目前能展示接口、模型、请求策略、执行状态和 Tokens，但无法判断请求最终由哪个 OAuth 账户处理。排查账户调度、失败切换和额度消耗时缺少关键线索。

## 目标

- 请求日志保存实际处理请求的账户信息。
- 详情抽屉展示请求时记录的账户别名或邮箱。
- 保留稳定账户键，便于后续定位同一账户。
- 不记录令牌、OAuth 原始账户 ID、认证文件路径或请求正文。
- 兼容旧日志，缺少账户字段时显示“未记录”。

## 数据模型

`RequestLogEntry` 新增两个可选字段：

- `account_key`：服务内部生成的稳定账户键，用于关联和诊断，不在当前详情界面直接展示。
- `account_alias`：请求发生时的账户别名或邮箱，用于详情抽屉展示。

两者随请求日志一起持久化。账户以后改名不会回写历史日志，保证历史记录反映当时状态。

## 账户选择语义

账户池使用请求局部上下文保存最近一次选中的账户：

- 请求成功：记录最终实际成功处理请求的账户。
- 发生账户故障转移后成功：记录切换后的成功账户。
- 请求最终失败：记录最后一次实际尝试的账户。
- 在选择账户前失败：账户字段为空，界面显示“未记录”。

请求局部上下文使用 `ContextVar`，避免并发请求互相覆盖账户信息。流式请求在流结束或报错后读取同一请求上下文中的账户信息。

## 接口与界面

管理接口返回的请求日志对象增加可选的 `account_key` 和 `account_alias`。主日志表格保持现状，避免横向列继续膨胀；点击日志后，在右侧“执行”区域新增“账户”，优先展示 `account_alias`，缺失时展示“未记录”。

## 兼容与安全

- 旧版 JSONL 日志没有新字段时正常加载为 `None`。
- 不改变现有请求接口和 OpenAI/Anthropic 兼容行为。
- 自定义客户端若没有账户元数据能力，日志仍可正常记录。
- 管理日志继续只展示安全元数据，不增加请求正文、响应正文或凭据。

## 验证范围

- 账户池成功、失败和流式路径能提供请求局部账户元数据。
- 请求日志新增字段能写入、读取并兼容旧记录。
- Chat Completions、Responses、Anthropic 的流式与非流式日志路径均带上账户元数据。
- 前端详情抽屉展示账户别名，并正确处理旧日志。
