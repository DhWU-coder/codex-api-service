# Web / CLI 双授权保留与回退

## 目标

同一真实账号只保留一个调度身份，同时分别保存控制台 Web 授权和全局 Codex CLI 授权。优先使用实际更新较新的凭据，只有明确认证失败时才尝试另一份；429、5xx 和网络失败不切换授权来源。

## 存储与兼容

- 每个账号新增 `authorizations/<source>/auth.json`，目录权限 0700，凭据和状态文件权限 0600。
- 状态文件只保存来源、实际更新时间、导入指纹和失效指纹，不保存令牌正文。
- 原有 `auth.json` 保留为当前授权的兼容镜像；旧凭据按已知来源迁移，不尝试恢复已经覆盖的历史授权。
- 相同导入指纹不会重置优先级，也不会覆盖服务已经刷新的同源凭据。失效指纹跨重启保留，两个来源内容相同也不能循环重试。

## 执行与并发

- 正常过期先按原来源刷新，刷新结果写回该来源。使用比较指纹的条件更新，旧刷新不能覆盖新登录。
- 每次实际 HTTP 请求的认证错误携带内部凭据指纹，迟到的旧请求只能拒绝自己使用的授权，不能误伤新授权。
- 普通请求和绑定响应链均先在原账号内回退；两份都失效后才沿用原有跨账号规则。绑定链禁止跨账号。
- 已输出 SSE 事件后不重放本次请求，但失效来源仍退出后续选择。
- 额度会话绑定到当前授权自己的目录，切换授权后淘汰旧会话，迟到结果不能覆盖新代次状态。

## 可观测性与边界

账号快照只暴露当前来源、两种授权的保存/失效/缺失状态和更新时间。前端兼容旧后端；不暴露令牌或指纹。两份授权仍属于同一账号、共享额度，也可能被上游同时撤销。
