# OAuth 登录会话生命周期修复设计

## 背景

Web 控制台启动 OAuth 登录后，后端会在 `.codex-oauth/pending/<session-id>` 下创建一次性 `CODEX_HOME`，并启动 `codex login` 子进程。当前页面关闭或刷新只会停止前端轮询，不会取消后端子进程，也不会释放后端的活动会话标记。因此用户再次点击“重新登录”时，会收到“已有 OAuth 登录正在进行”，并且遗留子进程可能长期等待。

## 目标

- 页面刷新或重新打开后自动发现并继续轮询仍在进行的登录。
- 用户再次发起登录时复用当前活动会话，不再返回冲突错误。
- 登录进行中提供明确的“取消登录”操作。
- 后端为无人完成的登录设置十分钟上限，超时后终止子进程并清理临时目录。
- 服务正常关闭时取消登录任务；服务重新启动时清理上次异常退出遗留的 `pending` 内容。
- 不删除或改写 `.codex-oauth/accounts` 下已经保存的 OAuth 凭据。

## 后端会话语义

`OAuthLoginManager` 仍只允许一个活动登录，但启动操作改为幂等：

- 没有活动会话：创建新会话并启动 `codex login`。
- 已有 `waiting` 会话：直接返回该会话快照，调用方接管现有会话。
- 活动标记指向已结束或不存在的会话：释放旧标记后创建新会话。

新增活动会话读取接口 `GET /admin/oauth/login/active`，固定返回 `{ "session": <快照或 null> }`。固定路径必须注册在动态的 `/{session_id}` 路由之前。

取消操作会先终止子进程，再取消并等待后台任务完成。后台任务统一负责把状态改为 `cancelled`、删除本次 `pending/<session-id>` 并释放活动标记，避免取消路径和执行路径并发清理。

## 超时与进程清理

后端等待 `codex login` 的最长时间为十分钟。超时后：

1. 终止仍在运行的子进程。
2. 等待标准输出和错误输出读取任务退出。
3. 将会话标记为 `failed`，提示“OAuth 登录超时，请重试”。
4. 删除本次临时目录并释放活动会话。

服务关闭时调用登录管理器的 `close()`，取消所有仍在等待的登录。管理器初始化时只清理 `pending` 目录中的遗留项，不触碰账号目录、账号索引和状态库。

## 前端交互

前端把“启动”和“观察”拆开：

- 应用初始化时读取活动会话；存在时立即显示并继续轮询。
- 点击“添加账号”“设备码登录”或账号卡片的“重新登录”后，使用后端返回的新会话或既有会话进入同一轮询流程。
- 同一个会话在一个页面内只启动一个轮询器，避免重复请求。
- `waiting` 提示右侧展示“取消登录”；取消成功后立即显示“登录已取消”。
- 登录成功后刷新账号列表，并沿用现有的三秒成功提示。

## 安全与兼容

- 管理接口继续使用现有本地鉴权。
- 返回值只包含会话 ID、状态、有限行数的 CLI 提示和导入后的内部账号键，不返回 token。
- 已完成会话仍短暂保留十分钟，兼容最后一次轮询。
- 已有账号凭据位于独立的永久目录；取消、超时、关闭和启动清理只作用于 `pending`。

## 验证范围

- 单元测试覆盖活动会话复用、活动状态读取、残留目录清理、取消等待和超时终止。
- 路由测试覆盖活动会话接口和重复启动复用。
- 前端 API 测试覆盖活动会话读取与取消请求。
- 界面测试覆盖刷新恢复轮询、取消按钮和重复发起接管。
- 后端、前端全量测试与前端生产构建全部通过。
